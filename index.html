Agents don’t fail at writing code. They fail at proving it’s done.

A chat message that says done is a claim. do-harness turns it into evidence: the agent reads guides before it codes, then runs computational sensors that the code itself has to pass. Exit code 0, or the work is not finished.

The harness is equally honest about its own limits. A workspace with zero sensors produces a vacuous pass, and the CLI reports VACUOUS rather than green, because a check that cannot fail proves nothing.

Exit codes

0
GREEN · all sensors passed
1
RED · a sensor failed
2
VACUOUS · zero sensors, nothing proven

init reports GREEN, RED, or VACUOUS, and exits non-zero on RED.

what red looks like

A failing run is data. With --record, every sensor result is written to agent_state.db as a beat and bumps that sensor’s error signature. Three consecutive failures and the sensor is halted: it stops running and reports failed until the fix lands. The agent cannot argue with a strike counter.

Language packs

rustnodewebgeneric

Each pack selects the sensors that fit the stack. The web pack adds axe accessibility, console noise, performance, visual diff, and i18n sensors on top of Playwright and Lighthouse.

Git hooks

pre-commit, commit-msg, pre-push. A fast sensor set on commit, the full suite on push.

Evidence and metrics

verify --record writes each sensor result into agent_state.db, append-only, and audit-chain recomputes the hash chain to report the first divergence. dora derives deployment metrics straight from git history, deterministic and read-only; metrics pr reports time-to-green and pushes per green.

Wire it in

  1. do-harness init

    Detects the pack, writes the contract, runs a first verification.

  2. do-harness hook install

    Gates commits and pushes through the sensors.

  3. do-harness verify --set verification --changed --strict

    The suite a change has to pass before it counts as done.

In CI

do-harness verify --format json --evidence .do-harness/evidence.json --strict

Exit 0 passes, 1 fails, 2 means usage or config error, or nothing runnable. A run that selects zero sensors exits 0 but is flagged vacuous in the JSON report — it is not verification evidence. No build step required.

Built for regulated loops

do-harness enforces deterministic, computational controls over the agent development loop: build-time verification sensors, workflow gates, tamper-evident logs, and machine-readable evidence artifacts. It claims build-loop assurance, not runtime policy.

The green path is dogfooded rather than assumed. CI runs init and verify on every push, and the test suite drives the real binary on fresh workspaces, asserting the pack goes green, then red once the crate is removed.
